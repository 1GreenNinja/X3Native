# Fleet LAN bus

Per-machine HTTP receiver + sender for **fleet-internal RPC over the LAN**. Each fleet PC runs a copy of `receiver.ps1` as a Windows Scheduled Task. Other fleet PCs POST messages to a target's receiver via `send.ps1`. Messages land in the target's `~/.claude/.lan_inbox.jsonl`, which the local Claude Code session (or its `/loop`) drains.

**Designed as a complement to the Slack daemon, not a replacement.** The LAN bus is:

| | Slack daemon | LAN bus |
|---|---|---|
| Audience | Tim (phone/laptop, anywhere on internet) | Fleet PCs (machine-to-machine, LAN-only) |
| Latency | ~5 min (daemon polls Slack every 5 min) | < 1 second (direct HTTP POST) |
| Rate limit | Slack API (~1 msg/sec/bot) | None — gigabit LAN |
| Auth | per-machine bot token (`xoxb-...`) | shared secret in `Authorization: Bearer <hex>` header |
| State | Slack's hosted message DB | local `.lan_inbox.jsonl` per machine |
| When CC is closed | message buffers at Slack | message buffers in `.lan_inbox.jsonl` |
| Right for | DJBOOTH ↔ Tim from anywhere | DJBOOTH ↔ 14900K coordinating gate / merge |

Both can run simultaneously without interfering.

## Architecture

```
Machine A (DJBOOTH)                            Machine B (14900K)
┌───────────────────────┐                      ┌───────────────────────┐
│  Claude Code session  │                      │  Claude Code session  │
│         │             │                      │         │             │
│  send.ps1 14900k "..."│                      │  reads .lan_inbox     │
│         │             │                      │         ▲             │
│         ▼             │                      │         │             │
│   HTTP POST           │   gigabit LAN        │   appendIncoming      │
│  to 14900k IP:47474 ──┼─────────────────────►│   receiver.ps1 (svc)  │
└───────────────────────┘                      └───────────────────────┘
```

## Files

| File | Purpose |
|---|---|
| `receiver.ps1` | HTTP listener on port 47474. Validates shared secret, appends valid messages to `~/.claude/.lan_inbox.jsonl`. Runs as Scheduled Task. |
| `send.ps1` | Helper to send a message to one or all fleet PCs. Looks up IPs from `~/.claude/.fleet_hosts.json`. |
| `bootstrap.ps1` | One-time setup: generates secret + placeholder hosts file + registers the receiver Scheduled Task. |

## State files (created on first run, not in this repo)

| File | Contents |
|---|---|
| `~/.claude/.fleet_secret` | 32-byte hex string. **MUST be identical across all fleet PCs** for auth to work. Generated by `bootstrap.ps1`; copy to other machines manually. |
| `~/.claude/.fleet_hosts.json` | `{ "machine-name": "192.168.x.x", ... }`. Edit per machine to reflect real LAN IPs. |
| `~/.claude/.lan_inbox.jsonl` | Append-only log of received messages. Drained + truncated by the local Claude Code session. |
| `~/.claude/.lan-receiver.log` | Rolling daemon log (last 200 lines kept). |

## Wire format

POST `/inbox` to `http://<target-ip>:47474/inbox`:

**Headers:**
```
Authorization: Bearer <hex-secret>
Content-Type: application/json
```

**Body:**
```json
{
  "from": "djbooth",
  "to":   "14900k",
  "text": "merge feat/portal-hub when you have a sec",
  "kind": "fleet-rpc",
  "ts":   1779943200000
}
```

**Response 200:**
```json
{ "ok": true, "ts": 1779943200124 }
```

**Response 401:** unauthorized (secret mismatch)
**Response 400:** malformed JSON or missing required fields
**Response 404:** wrong path or method

## Setup (per fleet PC)

```powershell
# 1. Clone repo (or pull tools/lan-bus/ via the fleet's git workflow)
cd D:\GameDev\X3Native

# 2. Run bootstrap
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\lan-bus\bootstrap.ps1

# 3. Add Windows Firewall rule (REQUIRES ADMIN — only needed for inbound traffic
#    FROM other fleet PCs. Loopback testing works without this.)
New-NetFirewallRule -DisplayName 'Fleet LAN bus (47474)' -Direction Inbound `
  -LocalPort 47474 -Protocol TCP -Action Allow -Profile Private

# 4. Reserve the urlacl so non-admin can bind (REQUIRES ADMIN, one-time)
netsh http add urlacl url=http://+:47474/ user=$env:USERDOMAIN\$env:USERNAME

# 5. Edit %USERPROFILE%\.claude\.fleet_hosts.json with each fleet PC's real LAN IP

# 6. Copy %USERPROFILE%\.claude\.fleet_secret to every other fleet PC
#    (the file's contents must match across the fleet)
```

## Test loopback (single-PC, no firewall needed)

After bootstrap:

```powershell
# Receiver is running as a scheduled task.
# From the same machine, send a message to localhost:
pwsh -File tools\lan-bus\send.ps1 djbooth "loopback test from $env:COMPUTERNAME"

# Check the inbox:
Get-Content $env:USERPROFILE\.claude\.lan_inbox.jsonl -Tail 1
```

## Test cross-machine (after firewall + 2nd PC bootstrapped)

## Migration path → Matrix

The LAN bus is a **stepping stone**. Once Matrix + Conduit + matrix-bot-sdk daemons are deployed (per `docs/superpowers/specs/2026-05-27-fleet-messaging-design.md`), the LAN bus can be:

1. **Kept as a fallback** — works offline / when Conduit is down for maintenance
2. **Used for low-latency fleet RPC** that doesn't need Matrix persistence (presence pings, "are you alive?" probes, ad-hoc commands)
3. **Retired** if Matrix proves to handle all fleet-internal use cases

The two systems can coexist indefinitely. The LAN bus has no monthly cost and no failure modes outside the LAN itself.

## Security notes

- **Shared secret in `Authorization: Bearer ...`** is the only auth. Anyone with LAN access + the secret can post. Keep the secret out of git (it's in `~/.claude/`, not the repo).
- **No TLS** — the LAN bus is plaintext HTTP. Tim's home LAN is trusted; if the threat model changes, swap to HTTPS with a self-signed cert and PowerShell's `Invoke-WebRequest -SkipCertificateCheck`.
- **No rate limiting** — the receiver accepts unlimited POSTs from authenticated callers. Not an issue for fleet-internal use; would need throttling if exposed beyond the LAN.
- **Firewall is the perimeter**. Don't open port 47474 to the public internet. The Cloudflare Tunnel handles internet-facing traffic via Matrix (different port, different design).

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `listener.Start() failed` | Port in use OR no urlacl reservation | Run `netsh http add urlacl...` as admin |
| 401 from receiver | Secret mismatch between sender + target | Re-copy `.fleet_secret` between machines |
| Connection timeout | Firewall blocking inbound 47474 | Run the `New-NetFirewallRule` cmd as admin |
| Scheduled task fails on logon | Wrong user identity OR Bash policy | Verify the principal in Task Scheduler GUI; toggle "Run with highest privileges" if needed |
| Inbox grows unboundedly | Local Claude session not draining | Verify `/loop` is running OR manually truncate `.lan_inbox.jsonl` after handling messages |
